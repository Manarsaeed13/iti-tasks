7. Retrieve the names of all employees in department 10 who work more than or equal 10 hours per week on "AL Rabwah" project.
SELECT E.name
FROM employee E, Emp_project EP, project P
WHERE E.ssn = EP.emp_num
  AND EP.pro_num = P.number
  AND P.name = 'AL Rabwah'
  AND EP.hours >= 10
  AND E.dep_num_fk = 10;

9. Retrieve the names of all employees and the names of the projects they are working on, sorted by project name.
SELECT E.name AS employee_name, P.name AS project_name
FROM employee E, Emp_project EP, project P

16. Display (Using UNION): a. The name and gender of the dependents whose gender is Female and who depend on a Female Employee. b. And the male dependents who depend on a Male Employee.
SELECT DEP.name AS dependent_name, DEP.gender
FROM Emp_dependences DEP, employee E
WHERE DEP.emp_num = E.ssn AND DEP.gender = 'female' AND E.gender = 'female'
UNION
SELECT DEP.name AS dependent_name, DEP.gender
FROM Emp_dependences DEP, employee E
WHERE DEP.emp_num = E.ssn AND DEP.gender = 'male' AND E.gender = 'male';


17. For each project, list the project name and the total hours per week (for all employees) spent on that project.
SELECT P.name AS project_name, SUM(EP.hours) AS total_hours
FROM project P, Emp_project EP
WHERE P.number = EP.pro_num
GROUP BY P.name;

 
18. Display the data of the department which has the smallest employee ID over all employees' ID.
SELECT D.*
FROM department D
WHERE D.dep_Number = (
  SELECT dep_num_fk FROM employee
  WHERE ssn = (SELECT MIN(ssn) FROM employee)
);


19. For each department, retrieve the department name and the maximum, minimum and average salary of its employees.
SELECT D.name AS department_name, MAX(E.salary) AS max_salary, MIN(E.salary) AS min_salary, AVG(E.salary) AS avg_salary
FROM department D, employee E
WHERE D.dep_Number = E.dep_num_fk
GROUP BY D.name;

Stored Procedures
1. Create a stored procedure to display all employees in a given department.
DELIMITER $$
CREATE PROCEDURE Show_Dept_Employees (IN p_dep INT)
BEGIN
  SELECT * FROM employee WHERE dep_num_fk = p_dep;
END$$
DELIMITER ;

2. Create a stored procedure that takes an employee SSN as a parameter and displays all employee information.
DELIMITER $$
CREATE PROCEDURE Show_Employee_Info (IN p_ssn INT)
BEGIN
  SELECT * FROM employee WHERE ssn = p_ssn;
END$$
DELIMITER ;

3. Create a stored procedure to increase the salary of all employees in a specific department by 10%.
DELIMITER $$
CREATE PROCEDURE Increase_Salary (IN p_dep INT)
BEGIN
  UPDATE employee
  SET salary = salary * 1.1
  WHERE dep_num_fk = p_dep;
END$$
DELIMITER ;
 
4. Create a stored procedure that returns the total number of employees in a given department.
DELIMITER $$
CREATE PROCEDURE Total_Employees (IN p_dep INT, OUT p_count INT)
BEGIN
  SELECT COUNT(*) INTO p_count FROM employee WHERE dep_num_fk = p_dep;
END$$
DELIMITER ;

5. Create a stored procedure to display the employee with the highest salary in each department.
DELIMITER $$
CREATE PROCEDURE Highest_Paid_Per_Dept ()
BEGIN
  SELECT E.dep_num_fk, E.name, E.salary
  FROM employee E
  WHERE E.salary = (SELECT MAX(salary) FROM employee WHERE dep_num_fk = E.dep_num_fk);
END$$
DELIMITER ;

5. Explain when indexes improve query performance and when they may reduce performance.
===Indexes improve performance when we have a large table and we frequently use WHERE, JOIN, or ORDER BY on a specific column, because it avoids a slow Full Table Scan.
===Indexes can reduce performance in these cases:
•	Frequent modifications: When the table has many INSERT, UPDATE, or DELETE operations (because the index must be updated every time).
•	Low Selectivity: When a column has many duplicate values (like gender, which only has two values).
•	Small tables: When the table is small, a Full Table Scan is faster than using an index.
•	Storage: Every index takes extra storage space on the disk.
